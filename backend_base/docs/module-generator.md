## 1. 定位与交付层次

### 1.1 功能目标

为 Backend Base 提供**可选择模块、可勾选功能、可预览产物的业务模板生成能力**，减少业务结构、接口、数据模型和分布式接入代码的重复搭建。

沿用 JDK 17、Spring Boot 3.5.9、MyBatis-Plus、MySQL、Redis、Sa-Token 和单 Maven 模块基线。输出进入现有 `backend_base` 工程，业务按包组织。模块生成指生成业务功能包，不额外嵌套一个 Spring Boot 项目或增加 Maven 子模块。

初始脚手架保持公共底座定位，18 类业务作为可选模板库按需生成。模板生成不局限于从数据库表反向产生 CRUD，还需表达功能组合、状态流转、约束、事务和外部系统适配。

### 1.2 三种交付层次

| 层次 | 生成结果 | 需要说明的内容 |
|---|---|---|
| L0：结构骨架 | 目录、类型、扩展接口、待补清单 | 尚未实现的流程和缺失依赖，不能返回伪造的业务成功 |
| L1：基础流程 | 参数齐全后可编译运行的本地业务流程、约束与测试 | 已完成的业务假设、必要配置、需要适配的系统 |
| L2：分布式场景模板 | 接入实际公共能力，附真实依赖下的并发和故障验证 | 已覆盖的场景、失败语义、恢复方式及剩余业务责任 |

每个功能分别标注层次和模板状态，不能因为模块有一个 L2 功能，就把整个模块标为 L2。L2 表示通过指定场景验证，不等于适用于所有生产业务的认证。

模板可处于“规划中、开发中、可用、已弃用”等状态。本文所有模板目前均为规划，表中的层次和优先级是目标，不是已交付能力。

### 1.3 公共能力与业务责任

公共组件提供锁、限流、短窗口防重，以及未来的缓存和消息机制；业务模板定义使用位置。数据库唯一约束、条件更新、业务流水、状态机和事务共同构成业务保证。

勾选“分布式事务”“最终一致性”“高并发”不能成为一个万能开关。界面必须将这些目标拆成具体功能及其保证，例如 Outbox、幂等消费、预占记录、失败补偿入口和结果查询。

## 2. 模块分类与边界

### 2.1 分类决定

| 类别 | 模块 | 组织方式 |
|---|---|---|
| 身份 | 用户 | 独立业务模块 |
| 交易 | 订单、支付、库存 | 分别独立，通过公开服务接口或事件协作 |
| 营销 | 秒杀、优惠券 | 界面归入营销组，内部保持独立子模块与表归属 |
| 账户 | 积分、钱包 | 业务模块和账本独立，共享可复用记账机制 |
| 查询 | 搜索、排行榜、报表统计 | 各自独立；缓存由公共层提供 |
| 通用业务服务 | 消息通知、文件管理 | 各自独立，对接公共投递机制或存储适配器 |
| 任务中心 | 定时任务、任务处理 | 界面归组；调度与执行采用不同职责和接口 |
| 行业流程 | 物流、工作流、预约 | 独立选配，根据领域规则生成 |

“合并”指功能导航分组或基础机制复用，不将不同业务的表、状态机和 Service 合成一个大模块。

### 2.2 需要从业务模块中抽出的机制

- 搜索模块专注索引、查询和同步；缓存、空值缓存、击穿保护复用 V2。
- 通知模块专注模板、收件人、渠道和发送记录；MQ 可靠发布/消费复用 V3。
- 积分与钱包复用流水标识、幂等键和事务约定，分别维护业务余额/积分及流水。
- 库存与预约可参考相似的资源分配机制，但库存数量模型与时间段预约规则分别建模。
- 定时任务负责何时触发，任务处理负责执行、重试与接管；超时订单等场景可绑定这些接口，不必强制生成完整任务中心。

## 3. 18 类模块规格

各项均支持按功能组合，具体文件清单在模板实现时补充到模板描述中。下列不含真正可执行的生产渠道、工作流引擎或搜索引擎适配器。

### 3.1 用户模块

- 功能：账号注册、登录/退出、当前用户、Token 有效期策略、共享会话、主动失效/踢人、并发和多端登录策略。
- 重复注册：规范化账号标识后依靠数据库唯一约束裁决并发注册；短信/邮箱验证按选定渠道接入。
- 生成内容：账号模型、身份验证服务、Sa-Token 会话接入、必要接口、唯一约束迁移、权限提供者扩展及测试。
- 固定要求：密码安全存储、账号状态检查、接口权限边界不能作为随意关闭的选项。账号验证不能直接信任客户端 userId。
- 依赖：现有 Sa-Token/Redis；登录限流可选 V1 的 IP/全局维度，避免给未登录接口配置必须先登录的用户维度。
- 验收：并发注册唯一、错误凭据拒绝、多实例会话与退出一致、踢人/有效期符合所选策略。Token 刷新若纳入后续模板，单列功能和协议，不暗示当前已有刷新实现。

### 3.2 订单模块

- 功能：订单创建、状态流转、幂等下单、取消、库存预占、超时关闭、可靠事件发布和处理。
- 幂等：持久下单请求号与用户范围的唯一约束、结果查询；V1 防重仅作短窗口入口保护。
- 超时：按互斥策略选择定时扫描或延迟消息，状态条件更新防止误关已完成订单。
- 事务：同库模块协作明确本地事务边界；跨服务流程可选 Outbox、幂等处理、补偿入口，不能通过注解自动替换本地事务。
- 生成内容：订单及必要明细/请求记录、状态转换服务、库存/支付协作接口、迁移与状态竞争测试。
- 验收：并发同请求仅创建一单；取消、超时与完成竞争时状态合法；重复释放库存不增加库存。

### 3.3 支付模块

- 功能：支付申请、支付流水、渠道适配、回调处理、主动查单、状态同步、退款和对账；退款/对账可后续独立交付。
- 固定要求：回调验签、商户/交易归属、金额和币种核对、合法状态转换、回调幂等。真实渠道接入时不能关闭验签后当作可用支付模板。
- 生成内容：支付与回调记录、渠道接口、状态机、订单关联标识、查询与异常处理入口。
- 一致性：结合查单、事件投递、消费幂等和对账形成可恢复流程，重复或乱序回调不得回退成功状态。
- 验收：重复申请/回调、错误签名、金额不符、先回调后请求结果、确认超时、退款重试。真实资金行为由渠道适配与业务验收确认，模拟渠道只进入演示包。

### 3.4 库存模块

- 功能：库存查询、直接扣减、预占、确认、释放、库存流水、校准/同步。
- 方案：每个接入点选择直接扣减或“预占—确认—释放”生命周期，不能混用两套扣减来处理同一库存变化。
- 约束：数据库条件更新限制可用数量，预占/流水业务键唯一；锁可辅助协调，数据库承担最终防线。
- 生成内容：库存与预占/流水模型、公开资源服务、业务键和状态约束、并发测试。
- 验收：不产生非法负库存、并发扣减有界、重复确认/释放不重复记账、异常回滚及同步事件重复/乱序处理。

### 3.5 秒杀模块

- 功能：活动规则、准入限流、Redis 库存预扣、请求去重、异步受理、订单创建、失败补偿、处理结果查询。
- 依赖：订单与库存服务绑定，V1 限流，异步方案所需 V3 MQ/可靠投递；Redis 预扣的原子脚本和去重规则由该模板实现并验收。
- 约束：受理成功与订单成功分别表达；Redis 与数据库库存之间明确事实来源、预扣有效期和补偿规则。
- 验收：限流、重复抢购、预扣后发送失败、消费失败、进程退出、补偿重复执行和结果查询一致性。必须以实际负载报告描述容量，不把“高并发”当作无条件性能保证。

### 3.6 优惠券模块

- 功能：券模板、批次、领取、并发发行额度、一人一券、锁券、核销、退回与过期。
- 规则：一人一券需明确范围为券模板、活动还是批次；核销需绑定业务单据且幂等。
- 生成内容：券模板与用户券、领取/核销流水、发行条件更新、唯一约束和状态转换。
- 验收：发行不超额、并发领取唯一、重复核销/退回有一致结果、核销与过期竞争合法。

### 3.7 积分模块

- 功能：积分账户、发放、扣减、冻结/解冻、流水、业务键幂等、可选到期策略和对账。
- 规则：积分采用明确的整数单位，额度/溢出检查；账户更新与流水在同一事务完成。
- 生成内容：积分账户及独立流水、公开记账接口、唯一业务键、条件扣减和异常查询。
- 验收：重复事件不重复加扣、并发扣减不突破规则、事务失败无半笔记录、账目可核对。

### 3.8 钱包模块

- 功能：钱包账户、余额查询、扣款、冻结/解冻、内部转账、记账幂等、流水和对账。
- 规则：金额使用整数最小货币单位或明确精度的 BigDecimal，禁止浮点金额；币种、精度、舍入和负余额策略显式配置。
- 转账：同库使用事务和固定顺序处理账户，借贷/转出转入记录保持可核对；跨库转账须另外设计状态机、补偿和可靠事件。
- 生成内容：独立钱包账户/流水、事务服务与约束；复杂账务、清结算不因生成基础模板而自动完成。
- 验收：并发扣款、重复记账、转账任一环节失败、死锁重试边界、流水与余额一致。与积分共享机制，不直接合并账本。

### 3.9 搜索模块

- 功能：搜索文档 DTO、查询、索引初始化/重建、增量同步、同步版本、失败重试和可选热点查询缓存。
- 适配：通过搜索引擎接口接入，具体引擎和版本在模板子任务开始前定稿；缓存绑定 V2，不重复实现通用缓存层。
- 一致性：明确数据库为业务事实来源，索引是可重建投影；更新和删除事件携带必要版本以处理乱序，重建考虑切换与并行增量。
- 验收：重复/乱序事件、删除、索引不可用后恢复、重建切换和缓存时效，查询权限不得因缓存命中被绕过。

### 3.10 消息通知模块

- 功能：通知模板、收件人、站内信/短信/邮件渠道、异步发送、发送记录、有界重试与失败重投。
- 分工：V3 承担消息投递机制，业务通知负责发送语义、渠道结果和频率规则。
- 生成内容：通知任务与结果记录、渠道适配接口、业务去重键、状态流转及运维查询。
- 验收：重复消息、渠道超时、结果未知、重试上限、失败恢复；对不支持幂等的外部渠道明确重复发送风险。

### 3.11 文件管理模块

- 功能：上传授权、分片上传、断点续传、分片校验/合并、文件元数据、存储适配、删除和废弃分片清理。
- 规则：分片和上传任务有归属、大小/数量限制、校验值和有效期；同一任务的重复分片/合并可识别。
- 存储：业务通过存储接口绑定实际对象存储，文件对象与元数据采用可恢复状态维护；不依赖单个应用实例的本地目录保存共享文件。
- 验收：跨实例续传、合并竞争、写对象后元数据失败、断连恢复、越权访问、孤儿文件清理和删除失败恢复。

### 3.12 定时任务模块

- 功能：任务定义、触发时间、调度、触发记录、分布式领取、分片规则、租约和故障转移。
- 规则：明确时区、漏触发/补触发、同一触发的唯一键；调度接口与执行接口分离。
- 生成内容：调度服务、运行记录、领取/续租/过期恢复机制或既有调度平台适配。
- 验收：两实例不重复领取同一有效执行权、租约恢复、分片范围和错过触发处理；任务业务仍须幂等，租约不能保证副作用只执行一次。

### 3.13 排行榜模块

- 功能：计分、幂等更新、排名查询、并列规则、周期榜、重置/结算和重建。
- 规则：Redis 有序集合可作为排名投影；明确事实来源、计分精度、同分排序及事件去重。
- 生成内容：榜单规则和查询 DTO、计分接口、周期命名空间、可恢复同步入口。
- 验收：重复/并发更新、精度边界、跨周期迟到事件、数据丢失后重建和榜单结算一致性。

### 3.14 物流模块

- 功能：运单、渠道适配、轨迹接入、回调验证、主动查询、事件去重和状态同步。
- 规则：外部事件可能重复、迟到或乱序；状态转换由规则限制，不直接覆盖最新状态。
- 生成内容：运单与轨迹记录、渠道接口、状态归并服务、补查与异常处理入口。
- 验收：重复/乱序轨迹、非法回调、渠道中断和补查恢复。依赖具体物流渠道，排在基础交易模板之后。

### 3.15 工作流模块

- 功能：流程定义、流程实例、任务分配、审批、状态流转、操作幂等、失败恢复与审计。
- 方案：简单审批状态机与外部工作流引擎适配是不同模板方案，开始实施前选择，不用一套伪通用模型承诺覆盖所有流程。
- 固定要求：审批人权限、操作版本检查、重复审批防护和审计保留。
- 验收：并发审批、重复操作、撤回/驳回规则、实例恢复和越权拒绝。复杂流程引擎模板后续单独规划。

### 3.16 报表统计模块

- 功能：统计口径定义、批量/异步聚合、增量统计、汇总、补算、校正与查询。
- 方案：实时与离线按统计需求选择，结果要说明数据截止点、时区和延迟。
- 生成内容：聚合任务、统计投影、去重/检查点和可恢复计算入口，具体指标由业务定义。
- 验收：重复事件、迟到数据、任务重跑、检查点恢复、补算与实时更新竞争，以及汇总结果校验。

### 3.17 预约模块

- 功能：资源定义、时段/容量、预约、重复预约保护、占用确认、取消、超时释放。
- 规则：明确时段是否固定、是否允许重叠、每人限制和资源容量；用数据库约束/条件更新与占用记录保证规则。
- 生成内容：资源/时段/预约与占用记录、状态服务、超时策略接入和并发测试。
- 验收：容量竞争、重复提交、确认与超时竞争、取消后的容量恢复和跨时区边界。

### 3.18 任务处理模块

- 功能：任务提交/分发、执行器、异步执行、领取租约、续租、重试、取消、结果查询和故障接管。
- 规则：明确幂等键、重试分类、最大次数、接管条件、超时与取消语义；过期领取者更新结果时校验领取令牌。
- 生成内容：任务/尝试记录、执行器接口、领取/状态服务及恢复入口，可由调度模块或 MQ 驱动。
- 验收：重复分发、执行后结果未落库、进程退出、接管竞争、超时与取消、旧执行者迟到结果。外部副作用仍需要业务幂等。

## 4. 模块与功能勾选规则

### 4.1 三层选择

```text
业务分组：交易
└── 订单模块
    ├── 基础模型与状态流转（必选）
    ├── 创建订单
    │   ├── 持久请求幂等
    │   ├── 短窗口防重复提交
    │   └── 库存预占接入
    ├── 取消订单
    ├── 超时关闭
    │   └── 方案：定时扫描 / 延迟消息（二选一）
    └── 可靠事件发布（需要尚未实现的 V3）
```

界面将分组、模块、可生成的功能分开。每项显示说明、必选/可选、完成度、依赖、所需中间件、生成文件数量、测试范围和当前可用状态。

### 4.2 选项约束

- 基础模型、必要状态、鉴权、金额/资源约束等保障流程合法性的内容是必选项或模板不变量，不能任意取消。
- 可选功能只带入自身及已确认依赖的产物；取消后重新计算依赖，保留仍被其他选项引用的内容。
- 依赖项可提示“同时生成”或“绑定已有能力”，不能偷偷勾选整套业务模块或整个中间件平台。
- 必选依赖显示锁定原因；互斥策略使用单选项；不可用功能禁用并显示原因及对应路线图。
- 同一模型被多个功能引用时只生成一次；选项组合不能产生重复表、重复 Controller 路由或重复状态处理器。
- 取消某项后若业务生命周期不完整，给出具体缺口并阻止生成 L1/L2，不能只生成创建入口而遗漏已承诺的确认/释放出口。

### 4.3 把目标变成可验收选项

| 目标 | 实际生成选项 |
|---|---|
| 分布式事务 | 本地事务边界、Outbox、幂等消费、补偿处理入口 |
| 支付最终一致性 | 回调去重、状态机、主动查单、异常对账 |
| 防止库存超卖 | 条件扣减、预占记录、幂等确认/释放 |
| 高并发秒杀 | 准入限流、Redis 预扣、异步受理、结果查询、失败补偿 |
| 可靠异步任务 | 持久任务、领取租约、重试预算、幂等键、接管与结果检查 |

不能仅在代码里留一个空方法或返回成功，就将功能标为已完成。

## 5. 依赖与方案互斥

### 5.1 条件依赖示例

| 所选功能 | 必要依赖或绑定 | 约束 |
|---|---|---|
| 用户共享会话 | Sa-Token、Redis | 必须先完成账号验证 |
| 订单库存预占 | 库存预占/确认/释放服务 | 可生成库存模块，也可绑定既有服务适配 |
| 订单超时关闭：扫描 | 可用的扫描执行/调度入口 | 扫描、分批、领取和状态条件更新需验收 |
| 订单超时关闭：延迟消息 | 可用 MQ 适配和幂等关闭处理器 | V3 未交付前不能宣称支持该方案 |
| 支付结果驱动订单 | 支付状态事件或公开协作接口 | 双向直接依赖改为契约/事件，避免 Mapper 耦合 |
| 秒杀异步下单 | 库存、订单契约、MQ、补偿与查询 | Redis 预扣不代表订单已经成功 |
| 热点查询缓存 | V2 缓存；加载保护还依赖 V1 锁 | 现阶段 V2 未实现，相关运行功能不可选 |
| 通知可靠投递 | V3、渠道适配、发送幂等策略 | 未接入实际渠道时只能是骨架或演示 |
| 钱包跨服务转账 | 状态机、可靠事件、幂等与对账 | 不用通用锁替代账务设计 |

只有选择了依赖该能力的功能，才引入相应依赖；基础订单模块不强制绑定支付、MQ 或完整任务中心。

### 5.2 方案互斥与组合检查

- 同一超时关闭接入点选择一个默认触发策略。需要扫描补偿消息时，应明确选择“消息主路径 + 扫描补偿”组合模板，并验证重复触发，而非无意生成两套独立主流程。
- 同一库存动作选择直接扣减或预占生命周期；同一事实不能重复扣减。
- 同一个既有服务绑定只能选“新生成实现”或“已有实现”，避免注册两个同职责 Bean。
- 简单审批模板与特定工作流引擎模板分别建模。
- 同库本地事务与跨服务事件方案按部署/数据归属选择，不能混用不兼容的事务假设。

依赖解析后检查有向图、缺失绑定、循环依赖、接口/Bean 名、表名、路由、事件类型及迁移冲突。跨模块通过公开契约协作，禁止为省事直接调用其他模块 Mapper。

### 5.3 当前能力与生成能力分别标注

| 层面 | 当前事实 |
|---|---|
| 公共底座 | Sa-Token/Redis 会话接入、V1 锁/限流/短窗口防重已经存在 |
| 后续公共能力 | V2 缓存、V3 MQ/Outbox、V4 完整观测尚未实现 |
| 模块模板 | 本文的 18 类模板和生成器均未实现 |

即使某项公共能力已存在，也不代表对应业务模板已经可生成。生成器读取能力目录与项目配置，展示“模板可用性”和“运行依赖就绪要求”两种信息，禁止混淆。

## 6. 输入参数与生成规格

### 6.1 输入来源

优先使用结构化表单/规格文件描述业务意图；数据库结构读取作为后续可选辅助，不作为唯一输入。已有表无法自动推断支付状态机、权限、资源释放和补偿规则。

| 输入类别 | 主要内容 |
|---|---|
| 项目 | 已绑定的项目根目录、基础包名、当前脚手架与能力版本 |
| 模块 | 模板 ID、业务包名、展示名称、模块实例别名 |
| 功能 | 功能 ID、可选参数、方案选择、目标完成度 |
| 数据 | 表名前缀、字段/精度/索引、唯一业务键、现有表绑定 |
| 接口与权限 | API 路径、操作权限标识、用户/管理端边界 |
| 业务规则 | 状态转换、数量/额度、超时、幂等范围、保留周期 |
| 外部适配 | 已有服务接口、支付/存储等提供者、配置引用名 |
| 产物 | 代码、SQL、配置建议、测试、文档是否生成及输出策略 |

使用凭据引用/占位符，禁止将真实密码、支付密钥、Token 写进规格、模板、预览或生成历史。

### 6.2 规格格式示意

以下展示表达方式，字段名在实现时定稿；不是当前应用配置，也不是完整可执行输入：

```yaml
specVersion: '1'
basePackage: com.istxicun.backend
completionLevel: L1
modules:
  - template: order
    packageName: order
    features:
      - order.create
      - order.cancel
      - order.submit-idempotency
      - order.inventory-reservation
    strategies:
      transaction: local
bindings:
  inventory:
    mode: existing
    adapter: project-inventory-service
outputs:
  code: true
  migrationMode: review-only
  tests: true
  documentation: true
```

该示例仍需按模板参数完成库存契约、状态规则和幂等键等校验。UI 勾选和后续 CLI/规格文件入口使用同一规格模型，依赖解析后形成不可变的生成计划。

### 6.3 校验要求

包名、Java 标识符、表/索引名、路由、模板参数分别校验；拒绝目录穿越、绝对路径注入、越界符号链接和不受支持的模板版本。项目输出根目录由本地工具绑定，不能由每次 HTTP 请求随意指定。

同一规格、模板版本、能力快照和已确定的迁移版本应产生相同业务文件。时间、计划 ID 等生成历史元数据与业务代码分开记录，避免每次预览无意义变化。

## 7. 生成产物与目录

### 7.1 产物清单

| 类别 | 生成规则 |
|---|---|
| Java 代码 | 按功能产生 Controller、Service、Mapper、Entity、DTO、协作接口和处理器，避免空层级 |
| 数据约束 | 结合状态与幂等需要生成索引、条件更新、流水/预占记录，不能只生成 CRUD |
| SQL | 默认生成待审查迁移候选；显式选择后才纳入 Flyway 管理目录 |
| 配置 | 生成功能配置建议及凭据占位；修改公共配置必须显示差异 |
| 构建依赖 | 对照 BOM/现有依赖去重，必要修改通过结构化 POM 变更预览 |
| 测试 | 单元测试、功能组合测试、必要的真实依赖并发/故障场景 |
| 文档 | 模块用途、启用参数、接入方式、状态机、错误码、限制与待补清单 |
| 生成记录 | 规格、模板版本、文件清单、内容摘要、依赖决策与应用结果 |

L1/L2 模板的必要约束和核心验收测试不可随意取消；可以选择不把测试写进目标项目，但模板发布前的自身验收仍为强制要求，预览应显示差别。

生成 SQL 不执行数据库变更。若选择写入 `src/main/resources/db/migration`，必须明确提示下一次应用启动时 Flyway 会执行它，并检查迁移版本冲突。默认 SQL 候选放在独立审查目录，由开发者确认纳管。

### 7.2 拟定业务输出

```text
backend_base/
├── src/main/java/<基础包>/modules/
│   ├── user/
│   ├── order/
│   ├── inventory/
│   ├── marketing/coupon/       # 选择相应模板时生成
│   └── tasks/worker/           # 选择相应模板时生成
├── src/main/resources/mapper/<模块>/
├── src/test/java/<基础包>/modules/<模块>/
├── generated/migrations/<计划>/ # 默认迁移审查候选，尚未实现
├── docs/modules/<模块>/
└── .module-generator/           # 拟定的规格、摘要与生成记录
```

包名可配置但须符合项目约定。跨模块共享类型复用 `common` 和 `distributed`，不复制一份统一响应、异常、锁或限流工具进每个模块。生成模板必须复用 `ApplicationIdentity`，不得另设会话/分布式命名空间；核心异常使用 `FailureCategory`，HTTP 映射放在 Web 适配层；业务跨域头通过 `app.cors` 配置扩展。生成结果纳入[架构保护规则](architecture-guardrails.md)验收。

Vue 业务页面生成属于后续独立扩展；首版的 Vue 界面是生成器自身的勾选/预览工具，不自动承诺生成 18 类模块的完整业务前端。

## 8. 生成流程与预览

### 8.1 用户流程

1. 本地启动生成工具，绑定目标 `backend_base` 工程并读取可用模板/能力目录。
2. 选择业务分组、模块和功能，查看完成度、必选项及尚未可用项。
3. 填写业务规则、数据、权限和服务绑定；按提示解决依赖与互斥。
4. 创建只读预览计划，展示文件树、每个文件的内容/差异、SQL、依赖、配置和待补项。
5. 开发者确认具体计划后应用。写入前重新检查规格、模板与目标文件摘要，变化后必须重新预览。
6. 输出写入结果、后续配置/迁移步骤、验证命令和人工接入清单。

预览不会修改项目、执行 SQL、启动 broker 或调用真实支付/存储渠道。生成记录不得把计划校验通过等同于业务验收通过。

### 8.2 拟定本地工具契约

| 操作 | 作用 |
|---|---|
| 获取模板目录 | 返回模块、功能、约束、依赖、参数和可用状态 |
| 创建生成计划 | 校验规格、解析依赖、渲染到暂存区并生成差异 |
| 获取计划 | 返回只读快照、文件树和验证结果 |
| 应用计划 | 校验计划版本和项目状态，执行已确认变更 |
| 查看历史 | 查询本项目已应用计划、版本和文件摘要 |

接口路径、启动命令和端口在实现时定稿。应用请求使用计划 ID/版本和摘要，不能由前端在“确认”时临时替换任意文件内容。

## 9. 已有文件与重复生成

默认只创建新文件，遇到冲突阻止应用并展示差异。生成器管理的文件通过历史摘要判断是否被修改：

- 内容相同：跳过并记录，无须重复写入。
- 已生成且开发者未修改：允许预览后更新。
- 开发者修改过或来源未知：默认保留，交由人工合并；首版不承诺智能 Java 合并。
- 公共 POM/配置：按结构修改并预览，不使用盲目的文本覆盖；真实凭据文件不进入备份或历史。

变更先在暂存区渲染和校验，应用时获取本项目生成锁、逐文件核对目标摘要，记录操作日志并保留必要备份。新文件使用防覆盖创建方式；更新和恢复须再次验证内容，避免覆盖 IDE 或其他进程刚写入的修改。

多文件写入不是天然的原子事务。失败时尽力恢复本次文件，恢复不了的路径要清晰报告；进程崩溃后根据日志提供恢复/人工处理入口。不能只返回“生成失败”却留下未说明的半套模块，也不能自动删除生成后已被用户修改的文件。建议使用 Git 检查生成差异与回滚。

## 10. 生成器实现结构

### 10.1 核心组件

拟按职责划分：模板目录/版本、规格校验器、依赖解析器、能力检查器、生成计划器、模板渲染器、差异预览器、文件应用器和生成历史。

模板使用带版本的描述文件声明参数、功能、依赖、互斥、文件集合及验收用例。渲染器拟采用 FreeMarker，模板仅来自受版本管理的可信模板库；自定义模板导入另设扩展边界，不执行远程上传的任意脚本。

模板发布前验证依赖图、受约束的功能组合、迁移与路由唯一性；基础层不因模板数量增加而堆入业务判断。新模板通过描述和受控扩展点接入。

### 10.2 入口与构建隔离

最终提供 Vue 3 的模块/功能选择、参数表单、依赖提示和差异预览。核心引擎与 UI 分离，同一规格模型可供本地文件/CLI 入口使用；避免两套入口产生不同结果。

生成器运行组件拟放在独立源码/构建 profile，输出与默认生产包隔离，仍保持单 Maven 工程。Vue 构建工具和 Node 版本在实现时锁定，普通业务工程构建不应因此必需 Node 或生成器前端依赖。

工具默认只在本机回环地址工作，具有独立的本地工具认证与写入校验，避免依赖尚未生成的业务账号模块。跨域请求、敏感信息输出和任意目录写入需明确限制。默认生产包不包含生成接口、模板管理入口或开发工具认证逻辑。

## 11. 实施阶段与优先级

以下是生成器自己的阶段，不等同于公共能力 V1～V4。首批完整验收聚焦**用户、库存、订单**，用三者验证结构、依赖和真实业务组合。

| 阶段 | 交付 | 门槛 |
|---|---|---|
| G1：生成内核 | 规格、描述文件、依赖/互斥、渲染、预览、文件保护及本地规格入口 | 支持可重复生成和失败恢复 |
| G2：首批模板与勾选界面 | 用户/库存/订单基础流程、Vue 勾选与预览、生成记录 | UI 和规格入口得到同一计划 |
| G3：首批分布式验收 | 共享会话、幂等订单、库存预占/释放、双实例并发与异常验证 | 通过模板及组合验收后标记相应功能 L2 |
| G4：模板库扩展 | 按基础能力就绪情况逐项扩展其余模块 | 每个功能独立标记状态和限制 |

扩展优先级：

- **P0**：用户、库存、订单的基础模型和可验证闭环。优先同库事务、数据库约束与 V1 接入；首批超时方案可采用受控扫描，不提前依赖未实现的 MQ。
- **P1**：支付基础、优惠券、积分、钱包基础、通知、文件、排行榜、预约，以及超时/异步场景需要的任务能力。按外部适配与验收成本拆成子任务，不能一次宣称全部完成。
- **P2**：秒杀完整异步链路、搜索索引同步、物流、复杂工作流、报表统计，以及复杂跨服务账务/转账。先等待所需的 V2/V3 或外部适配稳定。

18 类模块均保留在目录中。优先级表示实现顺序，不删除长期范围；尚未达到可用状态的功能不能作为可运行模板被勾选。

## 12. 验收标准

### 12.1 生成器验收

| 场景 | 必须满足 |
|---|---|
| 功能组合 | 必选项、依赖、互斥正确；取消后无悬空引用或多余处理器 |
| 能力缺失 | 清楚指出缺失公共能力/绑定；不能用空实现绕过 |
| 可重复性 | 相同规格和版本产生一致代码；同名模型去重 |
| 工程规范 | 单 Maven 模块、包和路由正确、复用公共类型，选定产物可编译 |
| 迁移 | 版本冲突可发现，SQL 默认待审查，不自动连接并修改数据库 |
| 预览一致 | 确认计划与写入文件一致；目标文件变化后拒绝旧计划 |
| 文件保护 | 路径越界被拒绝；已有修改不被覆盖；部分失败可定位和恢复 |
| 构建隔离 | 默认生产包无生成器 UI/API、开发凭据或模板工具入口 |
| 文档体验 | 干净检出可按 README 完成选取、预览、生成和验证 |

### 12.2 首批组合验收

- 用户：并发注册只保留一个合法账号，A 登录后 B 识别，退出/失效策略跨实例一致。
- 库存：并发扣减/预占不突破容量约束，重复确认和释放不重复改变数量，事务失败可恢复。
- 订单：持久请求号避免重复建单，幂等返回/查询规则清晰，取消与完成/超时竞争状态合法。
- 组合：订单失败后资源处理符合方案，预占有确认/释放出口，数据库约束、事务和公共锁的顺序经真实 MySQL/Redis 验证。
- 如绑定外部服务或未来 MQ，按所选方案新增断连、重复消息、结果未知和进程退出测试，不能拿同库测试替代跨服务验证。

### 12.3 组合测试策略

每个模板覆盖最小必选集、全功能集、依赖/互斥边界及参数边界；跨模板覆盖首批交易闭环和各外部适配方案。大量独立可选项采用受约束的两两组合等覆盖策略，关键资金/资源流程另设完整场景，避免把无法承受的全组合枚举作为唯一验收方法。

发布记录列出实际测试的规格、模板版本、运行依赖和未覆盖范围；不支持的组合在计划阶段明确拒绝。失败恢复和升级测试沿用同一批固定规格，防止模板迭代引入隐性变化。

### 可复用缓存能力

`cache-v2/envelope-1` 提供 `CacheClient`、`CacheKey`、`CacheType`、`CachePolicy`。
生成模板应复用这些 API 和 `app.distributed.cache`，禁止复制缓存实现或单独配置环境标识。
权限缓存键包含租户/用户范围，更新使用 `evictAfterCommit`；开启热点保护要求 V1 锁且加载在事务外。
配置与故障语义见 [V2 缓存](distributed-v2-cache.md)。

### 消息公共能力

`messaging-v3/envelope-1` 暴露 `MessageCodec`、`MessagePublisher`、`MessageHandler<T>`、
`ConsumerIdempotency`、`OutboxWriter`。Outbox 投递器维护批次租约，模板不得以确认等待时间推断端到端发布截止时间。
生成模板复用这些 API；不得生成直接 afterCommit 发消息
冒充 Outbox，不得以 V1 Redis 防重代替持久消费幂等。RabbitMQ 4.1 quorum 是唯一 broker 绑定，
使用 `app.identity` 隔离、显式消费者开关和独立 SQL 迁移位置。
模板仍须逐项验证本地事务边界、业务幂等、失败重放及外部副作用；公共能力实现不代表通知、订单等模板已实现。
接入及限制见 [V3 消息](distributed-v3-messaging.md)。
