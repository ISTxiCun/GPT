# 快速生成模块：需求与设计草案

**状态：需求收集中，尚未实现。** 本文先建立文档入口，具体支持生成哪些模块、生成哪些内容，等待用户补充后确定。当前没有生成命令、接口或可运行的生成器。

## 1. 功能目标

为脚手架增加快速生成模块的能力，减少重复搭建目录和基础代码的工作，使生成结果符合项目结构、编码约定及分布式公共能力的接入方式。

沿用项目当前的 JDK 17、Spring Boot 3.5.9、MyBatis-Plus、MySQL、Sa-Token 和单 Maven 模块基线。生成内容位于 `backend_base` 项目内，具体目录和文件范围随模块类型确定。

本文不预先定义模板清单，也不默认将“快速生成模块”等同于数据库表 CRUD 生成。模块含义和类型以用户接下来补充的需求为准。

## 4. 后续设计时需要明确的规则

以下为待评审事项，尚未作为生成器的既定实现：

- 生成结果如何保持单 Maven 工程与业务包边界，并复用现有公共类型。
- 如何校验模块名、包名和输出路径，确保写入范围符合项目约定。
- 如何在写文件前展示生成清单，以及处理已有文件与用户修改。
- 是否涉及修改依赖、迁移 SQL、环境配置；涉及数据库时，生成脚本与执行脚本的职责如何区分。
- 如何标识待补业务逻辑，使生成结果的可运行范围和业务完成度清楚可见。
- 如何验证生成结果可以编译、符合接口规范，并在需要时验证分布式能力。

## 5. 推进步骤

1. 用户补充希望支持的模块类型及预期内容。
2. 将需求整理为模块规格，确认每类模块的输入与输出。
3. 补充使用流程、模板组织、冲突处理、扩展方式和验收标准。
4. 明确首批实施范围后，再进入代码实现。
